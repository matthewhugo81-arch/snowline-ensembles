# Snowline Ensembles

Live site: https://matthewhugo81-arch.github.io/snowline-ensembles/

This repository is separate from the main Snowline dashboard. GitHub Actions publishes `docs/` to the existing GitHub Pages URL, including generated Met Office indexes. The original Snowline site is untouched.

A buildless dashboard using Snowline's navy and teal design. `npm start` serves a preview on 127.0.0.1:8796; `npm test` verifies chart calculations, binary source decoding, pressure masks, member IDs and run consistency. No synthetic forecasts are shipped to the website.

## Forecast sources

GFS ENS uses Open-Meteo `ncep_gefs_seamless` (31 members), EC ENS uses `ecmwf_ifs025_ensemble` (51), and GEM ENS uses `gem_global_ensemble` (21). Their issue times are read from the [provider metadata API](https://open-meteo.com/en/docs/model-updates) on the same `ensemble-api.open-meteo.com` service before and after each point forecast request. Model cards and individual charts show the date and UTC cycle separately from retrieval time. Changed or one-sided metadata is labelled unverified; newly available data is labelled updating for the provider's documented 10-minute consistency window. Metadata errors leave the forecast usable and its issue time unavailable, never guessed.

Every model card also checks its latest published run as the page opens, independently of location forecast downloads. GFS, EC and GEM use lightweight metadata requests; MOGREPS reads the published complete-run manifest. These checks refresh on the page's Refresh action and every five minutes while visible. A newer catalogue cycle never relabels an older plotted forecast: the card shows both times when they differ, and charts/exports retain their loaded-data timing. Simultaneous leading checks share requests; the post-forecast metadata check always makes a separate observation. Failed lookups show unavailable without guessing a cycle.

GEFS checks both `ncep_gefs025` and `ncep_gefs05`; different cycles are displayed separately. Upper-air temperatures use the 0.5° feed, while precipitation, snowfall and mean sea level pressure can use both. EC uses `ecmwf_ifs025_ensemble` metadata and GEM uses `cmc_gem_geps`. These times describe the latest reported feed initialization: the point API is a rolling forecast and can retain older runs at longer lead times. It does not guarantee one pinned run for every value. Hourly values may be interpolated by the provider. One past day is requested to support preceding-period totals.

MOGREPS-G is taken directly from the [free Met Office AWS dataset](https://registry.opendata.aws/met-office-global-ensemble/). All 18 members of 850 hPa temperature, 500 hPa temperature, total precipitation, snowfall and mean sea level pressure use the same verified initialization, grid point and member IDs. Member 0 is control; perturbed IDs are 1–17 at 00/12Z and 18–34 at 06/18Z. No deterministic temperatures or other models are substituted.

The source reaches +246 hours. Snowline samples temperature every 3 hours and sums native precipitation/snowfall intervals into complete 3-hour periods. Native accumulations are hourly through +132h, then 3-hourly from +135h. They cover the preceding interval, not the whole period since initialization. Six-hour totals sum two complete 3-hour periods. Lead-zero accumulations, missing constituent periods, fill values and below-ground pressure temperatures remain null. The UI disables 1-hour totals when MOGREPS is visible.

Mean sea level pressure is expressed in hPa. It is sampled at each displayed valid time, like temperature, and is never summed when the precipitation interval changes. Native Met Office pressure is converted from Pa to hPa; Open-Meteo supplies hPa. Temperatures are converted from Kelvin to Celsius. Precipitation is converted from metres of water to millimetres. Snow water equivalent is converted to centimetres using a fixed 7:1 snow-to-water ratio, matching [Open-Meteo's snowfall convention](https://github.com/open-meteo/open-meteo/blob/main/Sources/App/Controllers/VariableHourly.swift). This is a depth equivalent, not a prediction of settling snow. Snow signal is the share of available members with at least 0.1 cm in the selected interval, not calibrated probability.

Native nearest-grid extraction uses 0.1875° latitude × 0.28125° longitude. Temperatures below the surface are masked using the source's pressure flag, including at high terrain. Mean and 10th/90th percentiles include available members, including control. Comparisons align valid times; they do not imply matching initialization times between providers.

## Met Office processing and hosting

`.github/workflows/pages.yml` runs every three hours, on push, and manually. `scripts/index_mogreps.py` finds the newest complete run, validates source metadata, and creates compressed indexes of the required NetCDF/HDF5 byte ranges. It never downloads full model fields. Indexes are cached between builds and distributed with the Pages artifact; weather data is not committed to Git history. A failed update leaves the previous deployment intact. Indexes are retained for 48 hours so open browsers can finish their pinned forecast.

`server/index.ts` is deployed as the isolated `snowline-mogreps` Supabase Edge Function, with JWT verification enabled. It fetches only the source chunks needed for the requested grid point and time, checks file ETags, decodes the original float32 data and pressure flags, and caches each result in `public.snowline_mogreps_cache`. `server/schema.sql` enables RLS and restricts table access to the service role. Existing applications in the hosting project are unchanged. The browser contains only a public anon credential; the service credential is provided through the server environment and is never sent to the browser.

The UI pins one complete run, loads four forecast times concurrently, displays progress and preserves failures as gaps. Older indexes or cached four-variable responses keep the original charts usable while unavailable MSLP remains an explicit gap. Missing pressure is listed separately from whole-step failures and keeps the forecast marked incomplete until all five variables are available. All 83 times are loaded, supporting the full forecast horizon without further requests. Point results are cached by run/grid/time and expired after 72 hours. A cold location can take around a minute; cached points are faster. Actual run time, grid point and forecast end are visible. The free source is delayed after initialization; runs older than 24 hours are labelled, and runs older than 72 hours are rejected.

For local preview with live MOGREPS, copy the deployed `mogreps/latest.json` into the ignored `docs/mogreps/` folder. Forecast extraction uses the hosted endpoint. To rebuild indexes locally, use Python 3.12 with `scripts/requirements.txt`, then `python scripts/index_mogreps.py`. The `--probe` option indexes +24h and its constituent accumulation files without changing the latest pointer.

## Interface and exports

On phone screens (up to 760px), all panels share a denser UTC axis with stacked weekday, date and time labels. Typical five- and seven-day views retain daily markers; narrow weekly views abbreviate the date while the full month remains in each panel's visible UTC range. Longer views retain daily gridlines with spaced labels, and zoomed windows gain subdaily labels. Each mobile panel repeats the exact inspected time and has a linked slider, so inspection works without returning to the top controls. The desktop time axis and chart dimensions are unchanged. SVG and PNG exports keep the mobile date markers.

Automatic axes include member extremes. Manual/fixed scales report clipped values. Zoom and inspection are linked across panels. CSV includes coordinates, source, licence, retrieval time, verified run time where supplied, valid time, interval and actual member IDs; nulls are empty fields. Its `run_utc` field remains reserved for the verified Met Office run. Separate `feed_runs_utc`, `run_metadata_status` and `run_metadata_source` fields preserve source-specific Open-Meteo timings without presenting them as pinned per-point runs. SVG exports include the same chart-specific issue information, with wrapped footers for narrow views. MSLP CSV rows use `hPa` and `interval_hours=0` for instantaneous values; they retain the actual member IDs and chart-specific feed provenance. The pressure panel supports members, spread, comparison means, automatic/manual/fixed scales, linked zoom and inspection.

Panels are ordered: 850 hPa temperature, total precipitation, mean sea level pressure, snowfall signal, then 500 hPa temperature. All five panels open in their larger viewing size on desktop and mobile; each has a Minimise button. Members start in Multicolour, with Tonal available on both desktop and mobile. An explicit palette choice is saved under `snowline-ens-member-palette-v2`; older implicit defaults do not override the new starting preference.

The precipitation panel adds a blue **cumulative available-member ensemble mean**, using an independent right-hand millimetre scale. The original left scale still shows each preceding 1-, 3- or 6-hour total and retains its automatic, fixed and manual settings. In Members and Spread modes the cumulative curve uses the same period means as the chart, even when a member is missing; the bottom readout reports the minimum and maximum available-member counts across the accumulated periods. Compare means draws a separate cumulative curve and total for every model, with distinct blue line styles and one shared cumulative scale. No forecasts are blended.

Cumulative coverage is recalculated after every horizon, interval or linked-zoom change. It begins at zero at the first interval boundary at or after the visible start, and adds only complete adjacent periods ending strictly after that boundary and no later than the visible end. The period value plotted exactly at the left boundary covers time before the cumulative window and is excluded. Partial periods at either edge are excluded; the bottom readout gives the exact counted UTC span. A missing period, duplicate timestamp, or period with no available-member mean stops the known cumulative prefix. The line does not resume across the gap and the full-window total is unavailable, including when the requested window extends beyond a model's forecast. Zero-rain periods remain valid.

Linked inspection shows the cumulative value at the selected complete-period boundary. SVG exports retain the blue curve, right-axis label, model-specific total, counted UTC span, member availability and any incomplete-coverage status. CSV exports retain individual period/member rows and add `precipitation_cumulative_mean` rows plus `precipitation_visible_period_total`, with `member=ensemble_mean`. These derived rows use `mm`; `interval_hours` is elapsed counted coverage, not an additional period accumulation. The appended accumulation bounds, coverage status and member-count columns make the baseline, incomplete totals and time coverage explicit. Missing cumulative values are blank rather than zero, and derived precipitation rows retain the precipitation feed-run provenance.

Every chart has one image-menu button in its heading, with the same menu available by right-click, Shift+F10 or the context-menu key on the chart. **Copy image**, **Save PNG** and **Save SVG** use a snapshot of the current view taken when the menu opens. Images retain the selected theme, location, model/variable, exact viewed UTC bounds, source issue labels and credits. Precipitation includes its cumulative right axis, totals and coverage status; snowfall has its agreement-specific legend and selected period. The PNG renders the complete styled SVG at twice its dimensions without external images or fonts.

Copy starts the clipboard write directly in the user click, using a promise-backed PNG item so asynchronous rendering does not lose Safari's user activation. Unsupported or denied clipboard access opens a real PNG preview with native hold/right-click copying and a Save PNG link. SVG remains available if PNG conversion fails. The menu cancels transient chart gestures and closes with Escape without resetting the current zoom. It also supports arrow-key navigation and restores focus to its trigger. Downloads attach their anchor and retain the Blob URL for 60 seconds before cleanup.

Search uses Open-Meteo/GeoNames. The map uses Leaflet and OpenStreetMap. Favourites, recent places and theme are stored locally. Forecasts are held in browser memory until refresh. Shared URLs contain the selected location and model.
